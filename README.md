`/home/ubuntu/workspace/san-ai-releases`, пока предыдущая работает.

изменения схемы БД требуют отдельного согласованного обновления и резервной копии.

После изменений SSH-туннеля обновите адрес/порт в workflow и `BREV_KNOWN_HOSTS`.

Next.js-приложение с фронтендом и HTTP API для исследования организационной структуры. Sigma.js рисует граф через WebGL, Graphology хранит граф на клиенте. Интерфейс на русском языке.

**Это начальный стенд с моковыми данными, не реализация AI-анализа ТЗ.** В базе ровно 20 000 синтетических сотрудников, 20 департаментов, 200 отделов и один корневой узел: всего 20 221 узел и 20 220 связей. Имена, должности, города, структура и подчинение вымышлены и не отражают штат Казахтелекома. Документы пользователя не загружаются в БД и не отправляются внешним сервисам.

## Быстрый запуск

Нужен Node.js 22.23.2 (версия в `.nvmrc`) и npm. Пакеты фиксируются `package-lock.json`.

```bash
npm ci
cp .env.example .env.local
npm run db:seed
npm run dev
```

Откройте <http://127.0.0.1:3000>. На текущем компьютере Node.js установлен локально, без изменения системного PATH. Если `node`/`npm` не найдены, сначала выполните:

```bash
export PATH="$HOME/.local/share/hackaton/node-v22.23.2-darwin-arm64/bin:$PATH"
```

Это путь текущего Mac; на другом компьютере установите Node.js своим обычным способом.

В локальном режиме сервер и CLI должны использовать одну рабочую папку. **Перед `db:seed`, `db:migrate` или запуском второго сервера остановите первый процесс приложения:** PGlite предназначен для одного процесса, а не совместного открытия каталога несколькими процессами. Тесты используют отдельную временную БД.

## Что работает

- Первый уровень — круговой обзор: компания, 20 департаментов и генеральный директор; всего 22 узла.
- Нажатие на подразделение или сотрудника с подчинёнными открывает следующий уровень. Нажатие на конечного сотрудника открывает его карточку.
- Внутри любой ветки — дерево сверху вниз: выбранный объект наверху, его прямые подразделения и сотрудники ниже. На экран не загружаются все потомки.
- Сотрудники не исключаются по типу: директор виден внутри департамента, руководитель — внутри отдела, его сотрудники — внутри ветки руководителя.
- Хлебные крошки и «На уровень выше» позволяют вернуться к любому предку. Слева — быстрый переход к департаментам.
- До 24 дочерних объектов на первом уровне и до 12 внутри ветки; большие группы доступны через страницы без потери сотрудников. Карта вписана в доступную область; для исследования широкого дерева используются перетаскивание и масштабирование, без полос прокрутки.
- Поиск по имени/названию или ID, например `emp-20000`, открывает объект отдельной веткой с полным путём к компании. Поиск ограничивается текущим департаментом, до 20 совпадений.
- Масштабирование, перемещение, возврат к общему виду ветки и отключение связей.
- Рабочая область занимает высоту окна без вертикальной и горизонтальной прокрутки страницы. Статистика и заголовок компактные.
- Структура компании слева сворачивается в узкую панель; детали справа открываются по кнопке или выбору конечного сотрудника. Обе панели изначально свёрнуты, их списки прокручиваются внутри. На узких экранах развёрнутые панели накладываются на карту.
- Закрытие деталей не сбрасывает выбранный объект. При изменении размеров панелей Sigma подстраивает canvas через ResizeObserver.
- Состояния загрузки, пустой базы, отсутствия результатов, ошибки API и недоступности WebGL.

Всего в базе по-прежнему 20 000 сотрудников. В моковом наборе 21 существующая запись перераспределена на руководителей: один генеральный директор и 20 директоров департаментов. В первом департаменте 999 сотрудников, в остальных по 1 000, ещё один сотрудник относится непосредственно к компании.

Фронтенд использует `/api/branch`, а не загрузку полного графа. Радиальная и иерархическая раскладки рассчитываются детерминированно для одной страницы ветки. `/api/graph` сохранён для совместимости и проверки полного набора.

## База данных

Выбран PostgreSQL: для текущей иерархии достаточно таблицы узлов с внешними ключами и индексами. В дальнейшем рядом можно хранить документы, функции и источники; отдельная графовая БД на этом этапе не нужна. Векторный поиск и pgvector пока не установлены.

По умолчанию используется **PGlite** — PostgreSQL в WASM, работающий на сервере Next.js с постоянным каталогом `.data/pglite`. Docker не нужен. Данные сохраняются между перезапусками; каталог исключён из Git. Это локальный режим для одного процесса, не вариант многорепличного или serverless-развёртывания.

Для обычного PostgreSQL предусмотрен драйвер `pg` и `compose.yaml`:

```bash
docker compose up -d postgres
```

Затем в `.env.local`:

```dotenv
DATABASE_URL=postgresql://san:local_demo_only@127.0.0.1:5432/san
```

После изменения подключения выполните `npm run db:seed` и перезапустите приложение. Переноса данных между PGlite и PostgreSQL автоматически нет: один и тот же seed заполняет выбранную БД. Пароль в Compose — исключительно для локальной демонстрации; порт привязан к loopback. Docker/PostgreSQL-режим подготовлен, но не проверен в текущем окружении: Docker отсутствует.

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Подключение к PostgreSQL; пустое значение включает PGlite |
| `PGLITE_DATA_DIR` | Каталог локальной БД; по умолчанию `.data/pglite` |

`npm run db:migrate` применяет начальную SQL-схему. `npm run db:seed` сначала применяет её, затем вставляет демонстрационные записи в транзакции. Повторный запуск не дублирует записи и не перезаписывает существующие. Применяются две идемпотентные миграции: схема и перераспределение оригинальных моковых записей руководителей. Вторая миграция проверяет прежнего родителя и роль, сохраняя посторонние изменения. Механизм истории миграций ещё не внедрён.

## Парсинг DOCX — Document Intelligence

Доступен локальный парсер основного текста DOCX с сохранением абзацев и явно
записанных номеров пунктов. Результат совместим с проверкой цитат `verifySource`.
Файлы не отправляются внешним сервисам. Это текстовые фрагменты для будущего
AI-извлечения. Структурированное извлечение запускается отдельно в UI.

```bash
mkdir -p .data/document-parsing
npm run --silent documents:parse -- before "/путь/редакция_8.docx" > .data/document-parsing/before.json
npm run --silent documents:parse -- after "/путь/редакция_9.docx" > .data/document-parsing/after.json
```

`--silent` нужен, чтобы npm не добавлял служебные строки в JSON.
Папка `.data` исключена из Git; исходные документы также не следует коммитить.
Проверено на предоставленных редакциях 8 и 9: 491 и 490 непустых абзацев,
соответственно; текст и номера абзацев совпали с независимым чтением XML.
На Node.js 25.6.0 прошли 20 тестов (`npm test`), `npm run typecheck` и
`npm run lint` и `npm run build`; повторная проверка на Node.js из `.nvmrc` не выполнялась.

Ограничения и интерфейс: [docs/DOCX_PARSING.md](docs/DOCX_PARSING.md).

Что реализовано, результаты проверок и следующие шаги Full-stack 1:
[docs/DOCUMENT_INTELLIGENCE.md](docs/DOCUMENT_INTELLIGENCE.md).

## Прикрепление и хранение документов

Откройте <http://127.0.0.1:3000/documents> или кнопку «Документы ДО / ПОСЛЕ»
на главной. Выберите файлы или перетащите их в нужный комплект.

Поддерживается хранение DOCX/PDF/XLSX до 10 МиБ на файл. Текст извлекается
только из DOCX; для PDF/XLSX показано, что обработка ещё не подключена.
Можно скачать исходный файл и JSON текста DOCX.

Файлы сохраняются на диске сервера в `.data/documents` между перезапусками.
Каталог меняется через `DOCUMENT_STORAGE_DIR`, в Git не попадает.
Это общее локальное хранилище без авторизации; облачное хранилище не подключено.
Для деплоя необходим постоянный диск. API и ограничения — в [docs/API.md](docs/API.md).

## После загрузки документов

На `/documents` выберите DOCX в комплектах ДО/ПОСЛЕ и нажмите
**«Подготовить к сравнению»**. Будет вызван OpenAI API с текстом выбранных
документов. После извлечения появятся подразделения, функции, права и запреты
с цитатами, а также скачивание JSON обоих комплектов. Результат сохраняется
и доступен после перезагрузки страницы. Это извлечение, не готовое сравнение.

По умолчанию выбрана последняя обработанная загрузка каждой стороны. Для
повторных копий проверьте выбор. Формат интеграции и ограничения:
[docs/EXTRACTION.md](docs/EXTRACTION.md).

```bash
npm run ai:check-extraction
```

Эта проверка делает реальный AI-вызов только на синтетическом DOCX и проверяет
извлечение обязанности/запрета, сохранение, кэш и скачивание.
