# AI-извлечение документов

На `/documents` появился следующий шаг после прикрепления: «Подготовить к сравнению».
Выберите хотя бы один обработанный DOCX каждой стороны. По умолчанию выбирается
последняя обработанная загрузка ДО и ПОСЛЕ; остальные файлы добавляются в раскрываемом
списке. Это позволяет не запускать повторные копии случайно.

Кнопка запускает настоящее извлечение через OpenAI, проверяет цитаты и показывает
подразделения, функции, права, запреты и условия с источниками. Извлечение — ещё
не сравнение: потеря, перенос, дублирование и конфликт этим модулем не определяются.
Для следующего разработчика доступна выгрузка обоих комплектов в JSON.

## Запросы и сохранение

- `POST /api/documents/<id>/extract` — извлечь один DOCX; тело не требуется.
  Ответ `{ result: ExtractionResult, cached: boolean }`.
- `GET /api/documents/<id>/extract` — получить сохранённый результат без AI-вызова.
- `GET /api/documents/<id>/extract?download=1` — скачать результат как JSON.
- До завершения обработки GET возвращает 404. Одновременный POST для того же
  файла возвращает 409. Для необработанного/неподдерживаемого файла — 404.
- Результат атомарно сохраняется в каталоге документа как `extraction-v1.json`.
  Повторный запуск использует кэш. Изменение модели само по себе его не сбрасывает;
  использованная модель и дата сохранены в результате. Повторная загрузка оригинала
  создаёт новый документ и отдельное извлечение.

API-ключ используется только сервером. Текст выбранных документов передаётся
OpenAI, `store: false` задан в Responses API. Это не заявление об отсутствии
любого хранения у провайдера. Ключи и сырые ошибки провайдера не логируются.
Подключение соответствует [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Один запрос AI имеет таймаут 90 секунд, весь документ — 5 минут. До двух запросов
выполняются одновременно. Документ делится по абзацам на фрагменты до 14 тысяч
символов, максимум 12 частей; превышение отклоняется, а не обрезается молча.
Кнопка «Остановить» отменяет текущий запрос; уже готовые документы остаются сохранены.
Блокировка повторного запуска работает в одном Node.js-процессе локального MVP.

## Формат для интеграции

Типы: `src/lib/extraction.ts`. Это внутренний **extraction-v1**. Для общего контракта `DATA_CONTRACT.md`
добавлена проекция `toCanonicalOrganization`; общие типы графа не менялись.

Каждый `ExtractionResult` содержит:

- `schema_version`, `document_id`, `document`, `side`, `model`, `created_at`;
- `units`: `unit_id`, `unit_name`, `parent_unit`, `evidence`;
- `functions`: `function_id`, `unit_name`, `action`, `object`, `scope`,
  `responsibility_type`, `modality`, `conditions`, `evidence`;
- `processed_fragments`, `rejected_items`, `warnings`, `review_required: true`.

`modality`: `duty`, `permission`, `prohibition`; запреты не становятся обязанностями.
`responsibility_type`: `execution`, `oversight`, `approval`, `consulting`, `other`.
Неизвестные исполнитель, родитель, область действия и условия представлены `null`.
`evidence` — проверенные `VerifiedSource` с исходным текстом, цитатой и координатами
парсера. ID вычисляет сервер; модель не управляет идентификаторами документов.

Каждая цитата проверяется через `verifySource`. Записи с неверной структурой или
цитатой отклоняются и учитываются в `rejected_items`. Ошибка запроса или незавершённый
ответ не сохраняется как успешное извлечение. Успех обработки всех абзацев не
гарантирует, что модель нашла каждую функцию. Семантическая точность и полнота
требуют проверки человеком; кэш не является эталонной разметкой.

Названия и сокращения автоматически не отождествляются. Подразделения объединяются
только по одинаковому имени и родителю внутри документа; matching должен отдельно
разрешать переименования, сокращения и междокументные ссылки. Функция с неизвестным
исполнителем не должна автоматически считаться потерянной. Входные документы
рассматриваются как недоверенные данные, а не инструкции модели.

Кнопка скачивания ДО/ПОСЛЕ формирует `{ schema_version: "extraction-bundle-v1",
comparison_performed: false, before: ExtractionResult[], after: ExtractionResult[] }`.
Выгрузка ограничена выбранными документами, неполученные результаты не добавляются.

## Проверки

`npm test`: локальные проверки запретов, схемы, цитат, разбиения без потери
абзацев, отказов провайдера и существующих модулей.

`npm run ai:check-extraction`: реальный платный API-вызов на синтетическом DOCX
из трёх предложений, во временном каталоге. Проверены извлечение обязанности
и запрета, сохранение, кэш и скачивание. Пользовательские файлы команда не читает.

## Важное ограничение текущего извлечения

`units` сейчас содержит исходные упоминания организационных сущностей:
подразделения, должности и группы работников. Они не классифицированы по типу,
а варианты названия БВА могут остаться отдельными записями. Поэтому количество
`units` нельзя показывать как число уникальных департаментов или использовать
для вывода о создании/упразднении подразделения. Следующему модулю нужны
нормализация названий, классификация сущностей и сопоставление ответственности.

## Сверка с PRODUCT_SPEC 0.1 и canonical-выгрузка

`GET /api/documents/<id>/extract?view=canonical` возвращает
`{ contract_version, review_required, warnings, organization }` без вызова AI.
Для скачивания добавьте `&download=1`. Обычный GET и старая выгрузка из UI
сохраняют extraction-v1 для совместимости.

`toCanonicalOrganization(results, side)` объединяет выбранный комплект одной
стороны, исключает повтор одного document_id, связывает функции и источники по ID.
Типы владельцев: подразделение или должность; неоднозначное имя даёт null.
Имена между документами и сокращения автоматически не объединяются.

Новые извлечения запрашивают `entity_type: unit | position | unknown`.
Старый кэш без типа остаётся неизвестным: такие упоминания не включаются в units
или positions, функции сохраняются с null-владельцами и предупреждениями.
Автоматический повторный платный анализ кэша не выполняется. Для новой
классификации можно заново загрузить документ и выполнить извлечение.
Новая классификация проверена синтетически; реальные редакции 8/9 пока в старом кэше.

Разные типы ответственности теперь входят в ID функции, чтобы execution и
oversight не схлопывались. Старый кэш этот дефект ретроспективно не исправляет.

Соответствует текущему блоку: загрузка нескольких DOCX ДО/ПОСЛЕ, локальное
хранение, извлечение, проверяемые источники, canonical-проекция.
Остаётся в Document Intelligence: проверка классификации на реальных документах,
нормализация сокращений, полноценная иерархия, извлечение требований к должностям.
PDF/XLSX пока хранятся без парсинга; DATA_CONTRACT допускает DOCX-first на хакатоне.
Matching, findings, recommendations и results UI — блок Full-stack 2;
Workforce Alignment и корпоративные интеграции не добавлялись.
