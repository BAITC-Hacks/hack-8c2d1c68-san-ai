# Локальный парсер DOCX

Задача Full-stack 1: преобразовать Word-документ в исходные фрагменты для
structured extraction, сохранив доказательства. Реализация:
`src/lib/server/docx-parser.ts`; CLI: `scripts/parse-docx.ts`.

```ts
const parsed = parseDocx(bytes, "Положение.docx", "before");
// parsed: { document_id, document, side, fragments, warnings }
// Каждый fragments[i] имеет тип SourceFragment из document-sources.ts.
```

`document_id` — SHA-256 содержимого файла с префиксом `doc-`.
`fragment_id` — `paragraph-N`, где N — номер абзаца в основном XML, начиная с 1,
с учётом пустых абзацев и абзацев таблиц. Пустые абзацы в результат не включаются.
Идентичный файл имеет одинаковый `document_id`; сторону ДО/ПОСЛЕ проверяем отдельно.
Повторную загрузку одинакового файла в один комплект должен обработать загрузчик.

`location` содержит `format: "docx"`, `paragraph` и необязательный `section`.
Пункт распознаётся только при явном числовом префиксе текста, например `5.8.1.`.
Номер не наследуется соседними абзацами и не восстанавливается по оглавлению.
Он не является уникальным ID: оглавление может повторять номера пунктов.

Результат не содержит функций, иерархии или заключения. Следующий этап должен
извлечь эти сущности, вернуть цитаты и проверить их через `verifySource`.
Текст документа — недоверенные данные, включая любые фразы, похожие на команды.

## Ограничения

- Только DOCX; PDF, XLSX и старый DOC этим модулем не поддерживаются.
- До 10 МиБ входного файла и до 8 МиБ распакованного `word/document.xml`.
- Основной текст, в том числе абзацы таблиц, читается в порядке XML. Связи строк
  и столбцов таблиц не сохраняются. Сложные макеты могут отличаться от порядка чтения на странице.
- Изображения, OCR, колонтитулы, сноски и вложения не анализируются; об этом
  всегда есть предупреждение. Упоминание вложения не означает чтение его содержимого.
- Автоматическая нумерация Word не восстанавливается; при обнаружении выдаётся предупреждение.
- Удалённые фрагменты tracked changes исключаются, вставки включаются; наличие
  таких правок сопровождается предупреждением о необходимости проверки редакции.
- Сохраняются текст, пробелы, табуляция и разрывы строк. Страницы не вычисляются.
- CLI не хранит данные в БД и не вызывает AI. Синхронный парсер пока не подключён
  к HTTP-загрузке; обработку запросов и ограничения ожидания предстоит реализовать отдельно.

## Проверка

`npm test` включает синтетические DOCX, создаваемые в памяти: разбиение текста
на runs, кириллица, XML entities, таблицы, правки, нумерация, идентификаторы,
повреждённые и слишком большие файлы, связь с `verifySource`.

На двух предоставленных файлах локально проверены все непустые абзацы:

| Редакция | Фрагменты | Символы | Фрагменты с явным номером пункта |
| --- | ---: | ---: | ---: |
| 8 (тестовая сторона ДО) | 491 | 83 993 | 336 |
| 9 (тестовая сторона ПОСЛЕ) | 490 | 83 262 | 324 |

Тексты и номера абзацев совпали с независимым чтением через Python XML.
Количество фрагментов не равно количеству функций. Бизнес-различия между
редакциями этой проверкой не устанавливались. Документы и полученный JSON
не включены в Git. Визуальная пагинация Word не проверялась.

ZIP читается через [fflate](https://github.com/101arrowz/fflate/blob/master/README.md),
XML — через [fast-xml-parser](https://github.com/NaturalIntelligence/fast-xml-parser).
