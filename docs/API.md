# Начальный HTTP API

Все маршруты находятся в Next.js App Router, работают в Node.js и читают одну БД. Сейчас доступен только синтетический набор `demo-v1`. Это контракт реализованного стенда; будущий API анализа документов ещё не согласован.

## GET /api/branch — основной маршрут интерфейса

Параметры: `root` (по умолчанию `company`) и `page` (с нуля, по умолчанию `0`). Сервер возвращает только выбранный корень и страницу его непосредственных детей **любого типа**, включая сотрудников. Потомки более глубоких уровней не загружаются.

Ответ:

- `nodes`: поля `OrgNode` плюс `child_count` — число непосредственных дочерних объектов; координаты рассчитаны для текущей ветки.
- `edges`: связи от корня к детям текущей страницы.
- `breadcrumbs`: полный путь от компании до корня (включительно).
- `meta`: `mock`, `rootId`, `layout` (`radial` у компании, иначе `tree`), `nodeCount`, `edgeCount`, `totalChildren`, `page`, `pageSize`.

Размер страницы: 24 у компании, 12 у остальных объектов. У дерева координата Y родителя больше координат детей: в пространстве Sigma это соответствует расположению сверху вниз. Страницы сохраняют одинаковый порядок детей; сотрудники выводятся перед подразделениями.

Примеры после миграции демоданных:

| Запрос | Результат |
| --- | --- |
| `/api/branch` | 22 узла: компания, 20 департаментов, генеральный директор; круговая раскладка |
| `/api/branch?root=dep-01` | 12 узлов: департамент, директор, 10 отделов; дерево |
| `/api/branch?root=dep-01-team-1` | Отдел и его руководитель |
| `/api/branch?root=emp-00001&page=0` | Руководитель и первые 12 из 97 подчинённых |
| `/api/branch?root=emp-00004` | Конечный сотрудник, без дочерних объектов, с полным путём |

Неизвестный узел возвращает 404; некорректные параметры и страница за пределами диапазона — 400. Пустая мигрированная БД при запросе `company` возвращает пустой граф.

## GET /api/graph — полный набор, совместимость

Интерфейс поэтапного раскрытия этот маршрут не использует.

Параметры:

- `mode=overview` (по умолчанию): компания, департаменты и отделы.
- `mode=employees`: также сотрудники.
- `department=dep-01` … `dep-20`: ограничение департаментом. Без параметра или с пустым значением — вся организация. Корень включается для сохранения пути к компании.

Пример одного узла и одной связи; реальный ответ содержит все узлы выбранной области:

```json
{
  "nodes": [{
    "id": "dep-01", "label": "Сетевая инфраструктура", "kind": "department",
    "parent_id": "company", "department_id": "dep-01", "role": "Департамент",
    "city": "Алматы", "x": 1400, "y": 0
  }],
  "edges": [{ "id": "edge-dep-01", "source": "company", "target": "dep-01" }],
  "meta": { "mock": true, "mode": "overview", "nodeCount": 221, "edgeCount": 220 }
}
```

`kind`: `company | department | team | employee`. Связь означает подчинение либо структурную принадлежность, направлена от родителя к дочернему объекту. Граф включает только рёбра с обоими концами в ответе. Это один синтетический снимок, не доказательство бизнес-конфликта или реорганизации.

Полный граф: 20 221 узел, 20 220 связей. Первый департамент с сотрудниками и корнем: 1 011 узлов, 1 010 связей; остальные — 1 012 узлов, 1 011 связей. Генеральный директор привязан к компании, а не к департаменту. Постраничной загрузки полного графа пока нет; фильтр департамента ограничивает объём ответа.

## GET /api/search?q=emp-20000

Необязательный `department` ограничивает поиск. `q`: максимум 100 символов; менее двух значимых символов возвращают пустой массив. Поиск по `label` и `id`, без учёта регистра; `%` и `_` трактуются как текст, а не шаблоны SQL. До 20 результатов.

Ответ: `{ "nodes": [OrgNode], "limit": 20 }`; поля узла совпадают с `/api/graph`. Пустой результат: `{ "nodes": [], "limit": 20 }`.

## GET /api/health

```json
{ "status": "ok", "database": "pglite", "mock": true, "nodes": 20221 }
```

`database`: `pglite | postgresql`. Успех означает возможность прочитать таблицу; пустая, но мигрированная БД возвращает `nodes: 0`.

## Ошибки

- `400 { "error": "…" }` — некорректный режим, идентификатор департамента или слишком длинный поиск.
- `503 { "error": "…" }` — БД не готова или запрос не удалось выполнить. Технические подробности и строка подключения в ответ не включаются.

Авторизация и разграничение доступа не добавлены. Этот API нельзя открывать с реальными кадровыми данными без отдельной реализации доступа. Секреты подключения хранятся только на сервере в окружении.

## Документы: локальное файловое хранилище

Экран `/` (старый `/documents` перенаправляется) использует отдельное хранилище без зависимости от БД графа.

- `GET /api/documents` → `{ documents: StoredDocument[] }`.
- `POST /api/documents?side=before|after&name=<имя>`: тело — исходные байты
  одного файла, `Content-Type: application/octet-stream`; успех —
  `201 { document: StoredDocument }`. Имя передаётся URL-encoded.
- `GET /api/documents/<id>` скачивает оригинал.
- `GET /api/documents/<id>?view=parsed` скачивает JSON парсера для DOCX/PDF/XLSX,
  если текст успешно извлечён; иначе 404.

Типы: `src/lib/documents.ts`. Статусы: `parsed` — текст извлечён;
`stored` — старый файл без извлечения (нужна повторная загрузка); `parse_error` — оригинал
сохранён, но извлечение не удалось. Ни один статус не означает AI-анализ.

Лимит — 10 МиБ на файл, включая проверку потока без Content-Length;
ожидание тела запроса ограничено 30 секундами. Проверяются расширение и сигнатура,
а затем выполняется парсинг; ошибка чтения сохраняется как `parse_error`. Ошибки: 400 —
входные данные, 403 — чужой Origin, 404 — отсутствующий файл/результат,
408 — таймаут тела, 413 — размер, 503 — хранилище недоступно.

`DOCUMENT_STORAGE_DIR` задаёт каталог (по умолчанию `.data/documents`).
Каждая загрузка получает UUID-каталог с `original`, `metadata.json` и
необязательным `parsed.json`. Запись публикуется атомарным переименованием
временного каталога. Одинаковые имена не перезаписывают файлы; повторная
загрузка создаёт отдельную запись. Дедупликации и удаления через UI пока нет.

Это одно общее локальное рабочее пространство без авторизации и разделения
проектов. Для текущего MVP сервер слушает loopback. При развёртывании нужен
постоянный диск и контроль доступа; эфемерная файловая система serverless
для такого хранения не подходит. S3/MinIO не подключены.

## AI-извлечение

`POST /api/documents/<id>/extract` запускает извлечение подразделений и функций,
`GET` получает сохранённый результат, `?download=1` скачивает его.
Подробности, ограничения и формат: [EXTRACTION.md](EXTRACTION.md).
Это вход для будущего сравнения, не готовые findings.

### Canonical extraction

`GET /api/documents/:id/extract?view=canonical` — сохранённое извлечение в формате
`docs/DATA_CONTRACT.md`, обёртка `{ contract_version, review_required, warnings, organization }`.
Не вызывает AI. `&download=1` скачивает JSON. Неизвестные владельцы — null;
старый кэш без классификации сущностей возвращает предупреждения.
