# Проверка источников Document Intelligence

Реализован независимый модуль `src/lib/server/document-sources.ts`.
Он ещё не подключён к UI или AI: парсер и извлечение предстоит реализовать.
Это внутренний интерфейс проверки цитат, а не изменение общего canonical JSON.

## Как подключать

1. Парсер создаёт `SourceFragment` с уникальной комбинацией
   `side + document_id + fragment_id`. Имя файла не является идентификатором:
   в комплектах ДО/ПОСЛЕ могут быть файлы с одинаковыми именами.
2. Передайте извлечению текст и идентификаторы фрагментов.
3. Для полученной цитаты вызовите `verifySource(fragments, claim)`.
4. Только при `ok: true` используйте `source` как проверенную текстовую ссылку.
   Страница, пункт, лист и ячейки берутся из данных парсера, а не ответа модели.
5. При `ok: false` не публикуйте цитату как проверенную; обработайте причину
   `empty_quote`, `source_not_found`, `ambiguous_source` или `quote_not_found`.

PDF: фактическая страница (нумерация с 1), необязательный пункт.
DOCX: номер абзаца (с 1), необязательный пункт; страниц без рендеринга нет.
XLSX: имя листа и адрес ячейки/диапазона.
Парсер отвечает за корректность этих координат.

Проверка допускает различия в пробельных символах и переносах строк.
Регистр, пунктуация и слова не меняются. Возвращается точная подстрока исходного
текста с UTF-16 смещениями `start` и `end` (конец не включён).
При повторении цитаты в одном фрагменте берётся первое вхождение.

Совпадение цитаты подтверждает её наличие, но не правильность интерпретации:
например, модель может процитировать действие без предшествующего запрета.
Поэтому в результате сохранён полный `text` фрагмента для проверки контекста.
Модуль не подтверждает потерю функции, полноту комплекта или корректность OCR.

## Проверка

После установки зависимостей тест включается в существующую команду `npm test`.
Изолированная проверка без зависимостей на Node.js 22.18+:

```bash
node --test tests/document-sources.test.ts
```

Все данные тестов синтетические; внешние сервисы не вызываются.
