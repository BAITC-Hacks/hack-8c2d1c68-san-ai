# RESULT_UI_HOTFIX

**Priority:** P0  
**Goal:** минимально улучшить понятность результата анализа перед demo.  
**Scope:** только экран результатов и генерация простых рекомендаций. Не менять comparison engine, extraction, data contract и общий UX flow.

## 1. Убрать непонятную advisory-строку

Из основного экрана результата убрать текст:

> «ПОСЛЕ — предлагаемое состояние. Выводы и рекомендации требуют проверки и не изменяют текущую организацию.»

Для текущего сценария ДО/ПОСЛЕ эта формулировка сбивает пользователя.

Если юридическая оговорка нужна, оставить только внутри «Техническая информация»:

> Результаты носят рекомендательный характер и требуют проверки ответственным сотрудником.

---

## 2. Упростить alert неполного анализа

Текущий alert:

> «Анализ требует уточнения: некоторые источники не удалось надежно сопоставить...»

заменить на:

### Часть изменений требует уточнения

> Ниже показаны подтверждённые изменения. Для части функций автоматическое сопоставление не удалось, поэтому возможные потери могут быть определены не полностью.

Кнопку **«Повторить анализ»** оставить вторичной.

Не использовать формулировки, создающие впечатление, что весь анализ недостоверен.

---

## 3. Исправить карточки метрик

Сейчас при `analysis_complete=false` несколько карточек показывают одинаковое «Требует проверки». Это нужно убрать.

Правила:

- **Переданные функции** — всегда показывать количество подтверждённых findings `transferred`.
- **Дублирование** — всегда показывать количество подтверждённых findings `duplicated`.
- **Потенциальные конфликты** — всегда показывать количество подтверждённых findings `conflict`.
- **Возможно потерянные функции**:
  - если `absence_assessable=true` — показать количество `lost`;
  - если `absence_assessable=false` — показать **«Не оценено»**.
- **Новые подразделения**:
  - если создание можно оценить по текущим owner groups — показать количество `created`;
  - если нельзя — показать **«Не оценено»**.

Не использовать текст **«Требует проверки»** внутри summary cards.

Под карточками можно оставить одну общую подпись:

> Часть функций не удалось автоматически сопоставить. Это не влияет на уже показанные подтверждённые изменения.

---

## 4. Не оставлять вкладку «Рекомендации» пустой

Сейчас рекомендации создаются только для `lost / duplicated / conflict`. Если этих findings нет, вкладка пустая.

Добавить простые deterministic recommendations без нового AI-вызова.

### Если есть `transferred`

Добавить:

**Проверить полноту переноса функций**

> Убедиться, что переданные функции полностью закреплены за новыми владельцами и не осталось функций без ответственного подразделения.

### Если есть `created` или `transformed` owner groups

Добавить:

**Уточнить границы ответственности**

> Зафиксировать границы функций новых или преобразованных подразделений относительно сохраняющихся подразделений, чтобы снизить риск пересечения ответственности.

### Если есть `needs_review` matches или `analysis_complete=false`

Добавить:

**Проверить несопоставленные функции**

> Отдельно проверить функции, для которых система не нашла надёжного соответствия ДО/ПОСЛЕ, прежде чем считать перенос функций завершённым.

Эти рекомендации должны иметь статус `proposed` и не менять current/proposed organization.

---

## Definition of Done

Hotfix готов, если на текущем сравнении редакций 8/9:

1. нет основной строки «ПОСЛЕ — предлагаемое состояние...»;
2. alert неполного анализа читается как локальное ограничение, а не ошибка всего результата;
3. подтверждённые transfer / duplicate / conflict показываются числом;
4. недоступные для оценки показатели показываются как **«Не оценено»**, а не «Требует проверки»;
5. вкладка «Рекомендации» содержит минимум одну полезную рекомендацию, если есть переносы, изменения подразделений или несопоставленные функции;
6. comparison engine и data contract не изменены.
