# Что уточнить перед реализацией

Основание: [ТЗ](TZ.md) и [разбор исходного положения](AUDIT_SOURCE.md). Это открытые вопросы и предложения, а не согласованные решения команды. Для создания этих конспектов ответы не требовались.

## Вопросы организатору и PM

1. **Где полный комплект «до/после»?** К какому состоянию относится редакция № 9? Есть ли документы о реорганизации, положения других подразделений, штатные структуры и приложения?
2. **Каков контрольный пример?** Какие изменения, потери и дублирования в нём заранее известны? Предоставляется ли эталон для самопроверки?
3. **Какие файлы обязательны на демонстрации?** В ТЗ перечислены Word, PDF и Excel. Нужны ли старые форматы, сканы, распознавание схем и таблиц? Допустимость сокращения поддержки форматов пока не подтверждена.
4. **Какова глубина рекомендаций?** Краткие рекомендации входят в описание выхода, а рекомендации по перераспределению отдельно названы опциональными.
5. **Какие условия использования данных и AI API?** Допустима ли отправка документов выбранному внешнему сервису, какие доступны API и лимиты? Обезличенное имя файла само по себе не устанавливает условия использования.
6. **Как и когда сдавать?** Точное время, площадка показа и дополнительные требования к деплою, презентации или видео отсутствуют в изученном ТЗ.

## Решения команды, которые ещё не приняты

- Знакомый разработчикам стек, модель и способ её вызова.
- Границы MVP с сохранением пяти обязательных возможностей ТЗ.
- Разделение UI и обработки документов, контракт запроса/ответа, владелец общих файлов и интеграции.
- Место запуска и фактически доступный комплект данных для демо.

## Предлагаемые проверки результата

Это практическая детализация проверки из ТЗ, а не новые критерии организатора.

| Проверка | Ожидаемое поведение |
| --- | --- |
| Известная реорганизация | Правильно сопоставлены подразделения между состояниями; указаны основания |
| Известная потеря функции | Показана функция «до», источник и отсутствие найденного назначения в обработанном комплекте «после»; область проверки явно ограничена комплектом |
| Известное дублирование | Приведены оба назначения функции с источниками и объяснено пересечение области ответственности |
| Потенциальный конфликт интересов | Показаны несовместимые обязанности или ограничение и противоречащее ему назначение; вывод помечен как требующий проверки |
| Сохранённая или переданная функция | Переформулировка либо передача другому подразделению не объявляется потерей только из-за изменения текста |
| Общие обязанности руководителей | Совпадение формулировок при разных областях ответственности не объявляется подтверждённым дублированием |
| Проверка доказательств | Каждый существенный вывод ведёт к существующему документу и корректному пункту или фрагменту |
| Неполный или нечитаемый комплект | Понятно, чего не хватает; «не найдено в доступных данных» не превращается в доказанный факт утраты |

Контрольный набор должен включать случаи, перечисленные в разделе 11 ТЗ. Если команда создаст собственные изменённые документы для проверки, их нужно обозначить как синтетические и не выдавать за материалы организатора. В рамках этого разбора такие документы не создавались.
