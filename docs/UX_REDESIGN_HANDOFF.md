# Frontend redesign — передача работы

Дата: 23.09.2026. Основание: [UX_REDESIGN_SPEC.md](UX_REDESIGN_SPEC.md).

## Реализация

- Главный экран `/`: постоянный stepper «Документы → Структуры → Результаты».
  Этапы блокируются по готовности; возврат не удаляет состояние.
- Комплекты ДО/ПОСЛЕ показывают только выбранные файлы, имя, формат, размер,
  статус, оригинал и «Убрать из анализа». Работают несколько файлов, drag-and-drop,
  дозагрузка и добавление из сохранённого хранилища. Ошибка чтения не теряет файл.
- Состав сохраняется в localStorage; документы и извлечения остаются в прежнем
  серверном хранилище. Нет автоматического выбора всех исторических загрузок.
- «Построить структуры» вызывает прежнее фоновое извлечение; готовые данные
  используются повторно. Двойной запуск блокируется. После успеха — этап 2.
- Схемы ДО/ПОСЛЕ рядом, «Схема / Список», подразделения/должности и точные источники.
  При нескольких файлах каждая схема подписана документом; произвольного объединения
  названий между документами нет. Функции вынесены в закрытый дополнительный раздел.
- «Сравнить ДО и ПОСЛЕ» вызывает прежний comparison API; итог автоматически открывается.
  «Изменения» содержит метрики, finding cards, evidence и заключение. Подробная
  таблица функций и подразделения доступны отдельно. «Рекомендации» отделяет проблему,
  предложение, обоснование и источники, сохраняя proposed/current раздельными.
- Неполные/одинаковые данные не превращаются в нулевые метрики. Исходное серверное
  заключение при partial analysis доступно технически; основной текст не утверждает
  отсутствие рисков. Повторный анализ сохраняет предыдущий проверенный результат
  при ошибке. Провайдерские stack traces не выводятся в UI.
- Изменение комплекта показывает «Документы изменились», блокирует этапы 2/3
  до обновления структур. Простое перемещение между этапами не перезапускает AI.
- Design tokens: синий акцент, белые поверхности, холодный вторичный фон,
  отдельные success/warning/danger. Есть видимый focus, aria-live для обработки,
  native keyboard controls, адаптация ниже 900 px и reduced-motion.
- Tutorial только по «Как это работает?». Синтетический employee graph сохранён
  на `/structure`, но исключён из основного сценария.

## Реальные данные и границы проверки

Через настоящий API в браузере проверены выбор сохранённых редакций 8/9,
построение из их существующих extraction, схемы, источники, сохранённое сравнение,
детальная таблица, рекомендации/empty state, возврат и реальная повторная загрузка
редакции 8 с появлением stale-сообщения. Ошибок JavaScript не было.
Повторные внешние AI-вызовы для приёмки redesign не выполнялись.

У сохранённой реальной пары `analysis_complete=false`, `absence_assessable=false`,
нет подтверждённых findings/recommendations. Есть неоднозначные владельцы,
отклонённые извлечённые записи и неполные соответствия. Это существующее ограничение
качества Document Intelligence/comparison. Полный содержательный DoD с реальными
потерями/дублированием требует отдельно проверенного контрольного комплекта и
приёмки ответственным сотрудником. Пользовательское исследование с новым человеком
без объяснений разработчика не проводилось; автоматизация не заменяет эту приёмку.

OCR, HR/workforce, approval workflow и новые интеграции не добавлялись.
Общий storage по-прежнему без авторизации; новый UI не меняет этот серверный контракт.
Деплой этого redesign в рамках данной проверки не выполнялся.

## Передача второму разработчику

**DATA_CONTRACT, extraction-v1, comparison-v1, backend и comparison engine не менялись.**
Новых бизнес-полей нет. `src/lib/analysis-flow.ts` содержит только UI-ключи готовности
и правила отображения метрик. `DocumentWorkspace` управляет этапами, выбранными
UUID и polling. `ComparisonPanel` получает готовый `ComparisonResult` и callback retry.
Удалён прежний `ExtractionPanel`, его orchestration перенесён в workspace.

Добавлена только dev-зависимость `@playwright/test`; production-зависимости прежние.
Новый набор проверок запускается отдельно через `npm run test:ux`; unit-тесты не
требуют браузера. Следующий приоритет для demo — подтвердить реальные findings
на контрольной паре, сохраняя существующие проверки источников и human-in-the-loop.
